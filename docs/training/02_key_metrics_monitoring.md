## 指标优先级概览

根据对训练结果的影响程度，我们将指标分为四个优先级：

| 优先级 | 指标类别 | 监控频率 | 说明 |
|--------|----------|----------|------|
| P0 | 训练稳定性 | 实时 | 决定训练是否能正常进行 |
| P1 | 性能进展 | 每 10-50 步 | 决定模型是否在改进 |
| P2 | 探索与约束 | 每 50-100 步 | 影响探索效率和策略更新幅度 |
| P3 | 资源利用率 | 周期性检查 | 影响训练效率，不影响结果 |

---

## 第一优先级：训练稳定性指标

这些指标决定了训练是否能正常进行。如果这些指标异常，应该立即停止训练并排查问题。

### 1. `actor/grad_norm` - 梯度范数

**为什么重要**：梯度范数直接反映模型参数更新的幅度。

**健康范围**：0.1 - 10.0

**监控要点**：

```
✅ 健康状态：
   - 梯度范数稳定在 0.5-5.0 范围内
   - 波动平稳，没有突然的跳变

⚠️ 警告信号：
   - 梯度范数突然增大 10 倍以上
   - 梯度范数持续接近 grad_clip 值（默认 1.0）

❌ 严重问题：
   - 梯度范数为 0 或 NaN → 梯度消失
   - 梯度范数 > 100 → 梯度爆炸
```

**诊断与解决**：

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 梯度爆炸 | 学习率过大 | 减小学习率 50% |
| 梯度爆炸 | 数据异常 | 检查数据中是否有异常样本 |
| 梯度消失 | 学习率过小 | 增大学习率 |
| 梯度消失 | 模型收敛 | 检查是否已达到最优 |

---

### 2. `actor/pg_clipfrac` - 策略裁剪比例

**为什么重要**：反映 PPO 算法对策略更新的限制程度。

**健康范围**：0.1 - 0.3

**监控要点**：

```
✅ 健康状态：
   - clipfrac 在 0.1-0.3 之间波动
   - 随训练进行逐渐稳定

⚠️ 警告信号：
   - clipfrac > 0.5 → 策略更新过于激进
   - clipfrac < 0.05 → 策略几乎没有更新

❌ 严重问题：
   - clipfrac 接近 1.0 → 策略崩溃
   - clipfrac 持续为 0 → 模型停止学习
```

**诊断与解决**：

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| clipfrac 过高 | 学习率过大 | 减小学习率 |
| clipfrac 过高 | 优势估计不准 | 检查 Critic（GAE）或增加 n_repeat（GRPO） |
| clipfrac 过低 | 学习率过小 | 增大学习率 |
| clipfrac 过低 | 已收敛 | 检查验证指标 |

---

### 3. `critic/vf_loss` - 值函数损失（仅 GAE）

**为什么重要**：Critic 的准确性直接影响优势估计的质量。

**健康范围**：0.01 - 1.0（取决于奖励规模）

**监控要点**：

```
✅ 健康状态：
   - vf_loss 在训练初期下降
   - 稳定后在一定范围内波动

⚠️ 警告信号：
   - vf_loss 持续增大 → Critic 无法学习
   - vf_loss 完全不变 → Critic 可能死亡

❌ 严重问题：
   - vf_loss 为 NaN
   - vf_loss 无限大
```

---

## 第二优先级：性能进展指标

这些指标反映模型是否在持续改进。

### 1. `critic/score/mean` - 平均奖励分数

**为什么重要**：这是训练的直接目标，反映模型的整体性能。

**监控要点**：

```
✅ 健康状态：
   - 分数整体呈上升趋势
   - 存在一定波动，但总体向上

⚠️ 警告信号：
   - 分数长时间（>100 步）不增长
   - 分数开始下降

❌ 严重问题：
   - 分数持续下降
   - 分数出现 NaN
```

**典型曲线解读**：

```
分数
│    ╭───────────────  训练成功：分数稳步上升
│   ╱
│  ╱
│ ╱
│╱
└─────────────────────→ 步数

分数
│ ╭╮ ╭╮
│╱  ╲╱  ╲________  训练停滞：早期上升后平台期
│
│
│
└─────────────────────→ 步数

分数
│
│╲
│ ╲
│  ╲_______________  训练失败：分数持续下降
│
└─────────────────────→ 步数
```

---

### 2. `val-core/*/acc/mean@N` - 验证准确率

**为什么重要**：验证集上的表现反映模型的泛化能力。

**监控要点**：

```
✅ 健康状态：
   - 验证准确率与训练分数同步上升
   - 验证准确率稳定或缓慢上升

⚠️ 警告信号：
   - 训练分数上升但验证准确率下降 → 过拟合
   - 验证准确率大幅波动

❌ 严重问题：
   - 验证准确率持续为 0
   - 验证准确率远低于训练分数
```

**诊断与解决**：

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 过拟合 | 数据量不足 | 增加训练数据 |
| 过拟合 | 学习率过大 | 减小学习率，增加 KL 约束 |
| 验证低于训练 | 验证集分布不同 | 检查数据预处理 |

---

### 3. `critic/acc/mean` 和 `critic/format/mean`

**为什么重要**：分解奖励的来源，帮助理解模型的改进方向。

**监控要点**：

- **format 上升，acc 不变**：模型学会了格式，但内容质量没有提升
- **acc 上升，format 不变**：模型内容质量提升，但格式需要改进
- **两者都上升**：理想状态

---

## 第三优先级：探索与约束指标

这些指标影响策略探索的效率和更新的保守程度。

### 1. `actor/ppo_kl` - KL 散度

**为什么重要**：衡量策略变化幅度，过大可能导致不稳定。

**健康范围**：0.001 - 0.1

**监控要点**：

```
✅ 健康状态：
   - KL 在 0.01-0.05 范围内
   - 随训练进行逐渐减小

⚠️ 警告信号：
   - KL > 0.1 → 策略变化过大
   - KL < 0.001 → 策略几乎不变
```

---

### 2. `actor/entropy_loss` - 熵损失

**为什么重要**：熵反映策略的探索程度。

**监控要点**：

- 熵过低：策略过于确定，可能陷入局部最优
- 熵过高：策略过于随机，学习效率低

**解决方案**：调整 `actor_rollout_ref.actor.entropy_coeff`

---

### 3. `actor/kl_loss` - KL 损失（GRPO）

**为什么重要**：约束策略不要偏离参考策略太远。

**监控要点**：

- 应该在训练初期较大，随后逐渐减小
- 如果一直为 0，可能 `kl_loss_coef` 设置过小

---

## 第四优先级：资源利用率指标

这些指标影响训练效率，但不直接影响最终结果。

### 1. `perf/throughput` - 吞吐量

**为什么重要**：衡量训练速度。

**优化方向**：

- 增大 `batch_size`（如果显存允许）
- 增大 `gpu_memory_utilization`
- 启用 `use_torch_compile`

---

### 2. `perf/mfu/actor` - 模型浮点利用率

**为什么重要**：衡量 GPU 计算效率。

**健康范围**：0.3 - 0.6

**如果 MFU 较低**：

- 检查数据加载是否成为瓶颈
- 检查是否频繁进行显存 offload

---

### 3. `perf/max_memory_allocated_gb` - 内存使用

**为什么重要**：监控是否接近 OOM。

**监控要点**：

- 应该保持稳定，不应该持续增长
- 如果接近 GPU 显存上限，考虑减小 batch size 或启用 offload

---

## 健康训练曲线示例

### 理想的 GRPO 训练曲线

```
指标                     趋势
─────────────────────────────────────
critic/score/mean        ↗ 稳步上升
actor/pg_loss            ↘ 逐渐下降后稳定
actor/pg_clipfrac        → 稳定在 0.1-0.3
actor/ppo_kl             ↘ 逐渐下降
actor/grad_norm          → 稳定在 0.5-5.0
actor/kl_loss            ↘ 逐渐下降
val-core/acc             ↗ 稳步上升
```

### 理想的 GAE (PPO) 训练曲线

```
指标                     趋势
─────────────────────────────────────
critic/score/mean        ↗ 稳步上升
actor/pg_loss            ↘ 逐渐下降后稳定
actor/pg_clipfrac        → 稳定在 0.1-0.3
critic/vf_loss           ↘ 逐渐下降后稳定
critic/vf_explained_var  ↗ 逐渐上升到 0.5+
val-core/acc             ↗ 稳步上升
```

## 异常训练曲线诊断

### 情况 1：Loss 发散 (NaN/Inf)

**症状**：
- `actor/pg_loss` 或 `critic/vf_loss` 出现 NaN
- `actor/grad_norm` 突然变成 Inf

**诊断步骤**：
1. 检查学习率是否过大
2. 检查数据中是否有异常值
3. 检查梯度裁剪是否正常工作

**解决方案**：
```bash
# 减小学习率
actor_rollout_ref.actor.optim.lr=5e-7

# 确保梯度裁剪
actor_rollout_ref.actor.grad_clip=0.5
```

---

### 情况 2：训练停滞

**症状**：
- `critic/score/mean` 长时间不变
- `actor/pg_clipfrac` 接近 0

**诊断步骤**：
1. 检查学习率是否过小
2. 检查 KL 约束是否过强
3. 检查数据是否有多样性

**解决方案**：
```bash
# 增大学习率
actor_rollout_ref.actor.optim.lr=5e-6

# 减小 KL 约束
actor_rollout_ref.actor.kl_loss_coef=0.0001
```

---

### 情况 3：策略震荡

**症状**：
- `critic/score/mean` 大幅波动
- `actor/pg_clipfrac` 持续 > 0.5

**诊断步骤**：
1. 检查学习率是否过大
2. 检查 batch size 是否过小
3. 检查优势估计是否稳定

**解决方案**：
```bash
# 减小学习率
actor_rollout_ref.actor.optim.lr=1e-7

# 增大 batch size
data.train_batch_size=64

# 增加采样数（GRPO）
actor_rollout_ref.rollout.n_repeat=8
```

---

### 情况 4：过拟合

**症状**：
- `critic/score/mean` 持续上升
- `val-core/acc` 先升后降

**诊断步骤**：
1. 比较训练和验证曲线
2. 检查训练数据量

**解决方案**：
```bash
# 增强 KL 约束
actor_rollout_ref.actor.kl_loss_coef=0.01

# 减少训练步数
trainer.total_training_steps=200

# 降低学习率
actor_rollout_ref.actor.optim.lr=1e-7
```

## 快速诊断检查清单

当训练出现问题时，按以下顺序检查：

### 1. 基础检查
- [ ] 训练脚本是否正确启动？
- [ ] 数据是否正确加载？
- [ ] GPU 是否正常工作？

### 2. 稳定性检查
- [ ] `actor/grad_norm` 是否在正常范围（0.1-10）？
- [ ] `actor/pg_loss` 是否为有效数值（非 NaN/Inf）？
- [ ] `critic/vf_loss` 是否在下降（仅 GAE）？

### 3. 进展检查
- [ ] `critic/score/mean` 是否有上升趋势？
- [ ] `val-core/acc` 是否与训练分数同步？
- [ ] `actor/pg_clipfrac` 是否在 0.1-0.3 范围？

### 4. 效率检查
- [ ] `perf/throughput` 是否稳定？
- [ ] `perf/max_memory_allocated_gb` 是否接近上限？
- [ ] 各阶段耗时是否合理？
